🏠 Studio Overview & Architecture

Foundations

The VEX V5 LemLib Suite is an all-in-one web-based autonomous engineering platform designed specifically for VEX Robotics Competition (VRC) teams. Rather than forcing you to switch between separate drawing software, code editors, and telemetry terminals, the suite unifies all stages of autonomous development:

  • 2D Visual Path Planner & Field Simulator: Drag waypoints on the Override competition field, configure entry/exit velocities, specify subsystem actions (intakes, clamps, lifts), and simulate kinematics in real-time.
  • Full PROS C++ IDE: Multi-file development environment with cross-file variable parsing, AST syntax analysis, Monaco code editor, and ARM Cortex compilation.
  • Team Collaboration & Cloud Sync: Real-time multi-user editing with live collaborator cursors, 5-minute rolling OTP team join keys, and 500-snapshot version history.
  • V5 Brain USB Web Serial CDC: Direct connection from Chrome/Edge browsers to flash your compiled autonomous routines directly into V5 Brain program slots 1 through 8.
  • Autonomous Match Replay & Diagnostics: Import recorded odometry telemetry from the physical robot to compare planned versus actual trajectories and pinpoint wheel slippage.
💡 Tip for Competitors: The application runs fully offline once loaded, supports automatic saving to localStorage and Google Drive, and never exposes or overwrites your custom C++ header definitions.

📐 Field Coordinate System & Heading Conventions

Coordinate Math

LemLib and this Path Planner follow a standardized Cartesian coordinate framework mapped directly to the official 12-foot by 12-foot ($144\text{ in} \times 144\text{ in}$) competition field:

Property Standard Value Description & Orientation
Field Center (Origin) (0, 0) The exact geometric midpoint of the field tiles is coordinate $(0, 0)$.
X-Axis Range -72.0" to +72.0" $+X$ extends to the Right (East); $-X$ extends to the Left (West).
Y-Axis Range -72.0" to +72.0" $+Y$ extends Up (North); $-Y$ extends Down (South).
Heading Angle ($0^\circ$) 0° (North / +Y) $0^\circ$ corresponds to the robot pointing straight along the positive Y-axis.
Rotation Direction Clockwise Positive Headings increase clockwise: $90^\circ$ is East ($+X$), $180^\circ$ is South ($-Y$), $270^\circ$ is West ($-X$).

📁 Project Workflow & .vpath Files

Project Lifecycle

The suite uses a flexible single-file format called .vpath (VEX Path Planner Project). This JSON-formatted file contains all waypoints, robot physical dimensions, PID gains, custom code blocks, subsystem timings, and routine metadata.

Key Workflow Steps
  1. Create or Import: Click Workspace Tools ➔ Import .vpath or create a new routine from scratch.
  2. Configure Drivetrain: In the Bot & PID tab, set your track width, wheel diameter (e.g. 2.75" or 3.25"), gear cartridge (e.g. 600 RPM blue), and motor ratio.
  3. Add Waypoints & Subsystems: Click anywhere on the field canvas to add movement steps. Assign actions like intake.move(127) or clamp.set_value(true).
  4. Simulate: Press Space or click Play Sim to watch the simulated kinematics, check for barrier collisions, and verify total match elapsed time (≤ 15.0s for Autonomous, ≤ 60.0s for Skills).
  5. Sync to IDE: Switch to the PROS C++ IDE to compile the routine with pros make, run unit diagnostics, or flash directly to the connected Brain.

🎯 chassis.moveToPoint()

API Reference

Drives the chassis to a target $(X, Y)$ point on the field without enforcing a specific ending angle. Ideal for driving directly to game pieces or intermediate transit waypoints.

Signature (LemLib v0.5+) 
void chassis.moveToPoint(float x, float y, int timeout, MoveToPointParams params = {});
Parameter Type Default Description
x float Required Target X coordinate in inches.
y float Required Target Y coordinate in inches.
timeout int Required Maximum duration in milliseconds before timing out.
params.forwards bool true Set to false to have the robot reverse towards the point.
params.maxSpeed float 127.0 Top motor voltage speed limit (0–127).
params.minSpeed float 0.0 Minimum speed floor to prevent stalling at low power.
params.earlyExitRange float 0.0 Distance in inches before target to complete movement early for fluid chained motions.
Example C++ Usage 
// Move forwards to center ring stack at 110 max speed, exit 4 inches early for next motion
chassis.moveToPoint(0.0, 24.0, 2000, {
    .forwards = true,
    .maxSpeed = 110,
    .earlyExitRange = 4.0
});

🏎️ chassis.moveToPose() (Boomerang Controller)

Core Motion

The flagship motion primitive of LemLib. The Boomerang Controller guides the robot along a continuously curving path that guarantees the robot arrives at $(X, Y)$ facing exact heading $\theta$. It constructs an imaginary "carrot" target point along the vector of the desired final heading, pulling the robot into a natural, physics-optimized arc.

Signature (LemLib v0.5+) 
void chassis.moveToPose(float x, float y, float theta, int timeout, MoveToPoseParams params = {});
Parameter Type Recommended Description & Tuning Guide
x, y float Target Target destination coordinates in inches.
theta float 0–360° Target final heading at destination in degrees.
params.lead float 0.6 Curvature control parameter (0.0 to 1.0): A lead of 0.0 disables the boomerang and moves straight. Values between 0.5–0.7 create smooth sweeping arcs. Values > 0.8 create aggressive, wide hooks.
params.horizontalDrift float 2.0 Allows lateral drift during high-speed turns to prevent wheel scrubbing and motor heat buildup.
params.forwards bool true If false, the robot backs into the target pose (useful for goal clamps).
Example: Reversing to Clamp a Mobile Goal 
// Reverse into mobile goal at (-24, 36) facing 180 degrees
chassis.moveToPose(-24.0, 36.0, 180.0, 3000, {
    .forwards = false,
    .lead = 0.55,
    .maxSpeed = 95
});

// Fire pneumatic clamp asynchronously when 6 inches away!
chassis.waitUntil(6.0);
mogoClamp.set_value(true);

// Block until chassis finishes settle
chassis.waitUntilDone();

🔄 turnToHeading() & turnToPoint()

Angular PID

Performs an in-place pivot turn using the robot's angular PID controller. LemLib automatically takes the shortest angular distance across the $0^\circ / 360^\circ$ wrap boundary unless directional locking is specified.

Signatures 
void chassis.turnToHeading(float theta, int timeout, TurnToHeadingParams params = {});
void chassis.turnToPoint(float x, float y, int timeout, TurnToPointParams params = {});
💡 turnToPoint vs turnToHeading: Use turnToPoint(x, y) whenever aiming a ball launcher, catapult, or intake at a known field target. You don't have to calculate the trigonometry manually—LemLib queries current odometry pose and turns to face $(X, Y)$ precisely.

🪃 chassis.swingToHeading()

Swing Motion

Locks one side of the drivetrain while driving the other, causing the robot to swing in an arc pinned at one track. This is essential for pivoting tightly around perimeter field walls or mobile goals without kicking the opposite wheels into obstacles.

Example: Locking Left Wheel to Swing Tail Clear of Wall 
// Swing right side to heading 90 while keeping left side stationary
chassis.swingToHeading(90.0, lemlib::DriveSide::LEFT, 1500, {
    .maxSpeed = 90
});

🗺️ chassis.follow() (Pure Pursuit)

Pure Pursuit

Pure Pursuit follows pre-computed path files (e.g. exported from the planner) using a lookahead circle. The algorithm finds the intersection between the circle and the path ahead, steering smoothly toward it.

Pure Pursuit Path Execution 
// Follow path asset with 15.0 inch lookahead radius
chassis.follow(auton_path_txt, 4000, 15.0, {.forwards = true});

⏱️ chassis.waitUntil() & Asynchronous Subsystems

Non-Blocking Actions

LemLib executes movement commands in a dedicated FreeRTOS background task. This means your code does not block after calling chassis.moveToPose()! You can run parallel code while the robot is driving:

  • chassis.waitUntil(float dist): Pauses the calling task until the robot is within dist inches of its target.
  • chassis.waitUntilDone(): Blocks until the movement finishes and settles within tolerance.
  • chassis.isInMotion(): Returns true if the chassis is actively tracking a motion profile.

📍 chassis.setPose() & Odometry Calibration

Odometry

Every autonomous routine MUST begin by initializing the starting odometry pose. If you start aligned against the field perimeter wall or tile corner, set the coordinates at the top of autonomous():

Odometry Initialization (src/autons.cpp) 
void autonomous() {
    // Set robot start location: X = -54.0, Y = -36.0, Heading = 90 deg East
    chassis.setPose(-54.0, -36.0, 90.0);

    // Start motion routine...
}

💻 PROS C++ IDE & 2-Way Code Synchronization

IDE Studio

The embedded PROS C++ Multi-File Coding Studio allows seamless editing between graphical visual blocks and native C++ code:

  • Two-Way Synchronization: Edits made in the visual flowchart update src/autons.cpp. Conversely, typing C++ in the IDE parses functions directly back into flowchart waypoints.
  • Raw C++ Preservation: Complex logic like while-loops, custom sensor readings, or custom function calls inside autonomous() are preserved intact without being stripped.
  • Cross-File Device Indexing: The IDE indexes motor definitions and pneumatics declared in include/robot-config.h and offers autocomplete inside the visual flowchart action picker.

🎛️ PID Tuning Guidelines (kP, kI, kD)

PID Tuning

LemLib utilizes two primary PID controllers: Lateral PID (distance error along the path) and Angular PID (heading error). Proper tuning ensures rapid settling without oscillations:

Gain Role in LemLib Tuning Procedure
kP (Proportional) Applies output proportional to distance/heading error. Start at 0.0. Gradually increase until the robot drives to the target quickly and begins slight oscillation around the endpoint.
kD (Derivative) Dampens velocity to eliminate overshoot. Increase kD to brake gently as error shrinks, eliminating oscillation and overshoot.
kI (Integral) Eliminates steady-state error caused by carpet friction. Keep at 0.0 or very low (e.g. 0.001). Only activate within a small integral error window to prevent integral windup.

👥 Real-Time Team Collaboration & Security

Collaboration

Teams can edit autonomous paths concurrently during pit meetings. Up to 10 teammates can open the same workspace with live collaborator cursors, pinned match comments, and instant cloud sync.

Security Architecture: 5-Minute Rolling OTP & 6-Digit Hex Challenge
  • 5-Minute Rolling OTP: When joining a team workspace via team code, teammates must enter the live 6-digit rolling OTP displayed on the team owner's dashboard. The OTP changes every 5 minutes to prevent unauthorized spectator access.
  • 6-Digit Hex Verification Challenge: Administrators can invite teammates by Gmail address. When the invited user signs in, a full-screen challenge presents 3 hexadecimal codes. Selecting the correct code immediately enrolls the member with designated permissions.
  • Admin vs Member Roles: Only workspace owners and admins can modify motor configurations, alter permissions, or deploy routines to the connected Brain. Regular members can edit in "Suggestion Mode".

📊 Autonomous Match Replay & Log Analysis

Diagnostics

Have an autonomous run fail on the field? Log odometry values to an SD card on the V5 Brain during matches:

SD Card Logging Loop Example (PROS C++) 
FILE* logFile = fopen("/usd/auton_telemetry.csv", "w");
fprintf(logFile, "time,x,y,theta\n");
while (true) {
    lemlib::Pose pose = chassis.getPose();
    fprintf(logFile, "%d,%.2f,%.2f,%.2f\n", pros::millis(), pose.x, pose.y, pose.theta);
    pros::delay(20);
}

Drag the resulting CSV file into 📊 Match Replay in the studio. The tool overlays the actual recorded trajectory onto your planned visual path, generating a deviation heatmap that highlights where the robot slipped or lost odometry tracking!

❓ Frequently Asked Questions & Troubleshooting

FAQ
Q: Why is my robot taking a huge loop instead of a tight curve with moveToPose?

A: This happens when the lead parameter is too high or the target heading $\theta$ requires a sharp turnaround that exceeds the robot's turning radius. Try lowering lead from 0.6 to 0.3 or inserting an intermediate moveToPoint waypoint.

Q: Why does my robot spin in the wrong direction during turnToHeading?

A: Check your inertial sensor calibration in robot-config.h and make sure the IMU is mounted securely with low vibration. Remember that angles increase clockwise ($0^\circ$ North, $90^\circ$ East). If your IMU is mounted upside down, invert the rotation in your odometry configuration.

Q: How do I connect the V5 Brain over USB on Linux or Chromebook?

A: On Linux, ensure your user account belongs to the dialout group to access Web Serial CDC devices without root permissions: sudo usermod -a -G dialout $USER.

Q: Can I mirror a Red Alliance routine to Blue Alliance automatically?

A: Yes! Open Workspace Tools ➔ Alliance Routine Mirror. You can choose horizontal reflection ($X \to -X$), vertical reflection ($Y \to -Y$), or rotational inversion ($180^\circ$ point symmetry).
