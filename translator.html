❓ C++ Auton to Visual Blocks & LemLib FAQ

Everything you need to know about parsing C++ autonomous routines into visual blocks, handling LemLib v0.5+ structs, and synchronizing with your robot slots.

1. How does the C++ parser convert code into visual blocks?

The parser uses robust regex pattern matching to scan your C++ source for LemLib methods like moveToPoint, moveToPose, turnToHeading, and subsystem calls (e.g. clamp.set_value, intake.move). It extracts coordinates, timeouts, and parameter structs (like .forwards, .maxSpeed, .lead) into structured visual action blocks.

2. What LemLib v0.5+ syntax is fully supported?

It supports chassis.setPose(x, y, theta), chassis.moveToPoint(x, y, timeout, opts), chassis.moveToPose(x, y, theta, timeout, opts), chassis.turnToHeading(theta, timeout, opts), chassis.swingToHeading(...), and designator structs with .forwards, .maxSpeed, .minSpeed, .earlyExitRange, and .lead.

3. How are asynchronous tasks & concurrency handled?

When the parser detects pros::Task declarations or {.async = true} flags, it tags the resulting visual block as an Async Subsystem Task. This ensures your intake, indexers, or pneumatics spin up concurrently while the chassis executes motion.

4. Where do parsed blocks go when I click Apply?

When you click Apply to Visual Planner & Slot, the translated actions are saved directly into your selected autonomous slot (e.g. Autonomous Slot 1 - 8) and profile. They instantly populate the Visual Path Planner canvas and simulation timeline!

5. Can I edit blocks visually after translating?

Yes! Once loaded into the Visual Path Planner, you can drag waypoint handles on the 144×144 field, modify speeds, toggle intake actions, reorder steps, or re-export back to clean C++ code anytime.

6. What happens to my custom comments?

Any inline comments (e.g. // score alliance stake) associated with action lines are preserved as description notes on the respective visual blocks for documentation and engineering notebook clarity.
